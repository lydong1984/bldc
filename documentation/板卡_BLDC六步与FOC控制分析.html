01 / 应如何分类

板卡名称不能直接决定控制算法。同一套三相逆变硬件通常可承载六步控制和 FOC；本工程中，Make 选择的是硬件引脚、采样和驱动配置，最终算法由 mc_configuration.motor_type 与硬件限制宏共同决定。名称带 FOC 不等于只能 FOC，名称带 dual 也不等于固件启用了双电机。

BLDC 六步控制的实现

motor/mcpwm.c 用 comm_step 表示 1～6 个换相状态，通过 set_next_comm_step() 设置各相输出。无感模式根据相电压/反电动势推进换相，有感模式使用霍尔表。电流环、速度环等外层控制不会将六步换相自动变成 FOC。

FOC 控制的实现

motor/mcpwm_foc.c 对采样电流执行 Clarke / Park 变换，在转子 d/q 坐标系调节电流，再经逆 Park 变换和 foc_svm() 输出 PWM。霍尔、编码器和无感观测器属于角度来源选择；使用霍尔并不意味着采用六步控制。

motor/motor.mk 同时列入：motor/mcpwm.c + motor/mcpwm_foc.c

MOTOR_TYPE_BLDC = 0 → mcpwm_init(...)     → 六步换相
MOTOR_TYPE_DC   = 1 → mcpwm_init(...)     → 有刷 DC（不计入六步分类）
MOTOR_TYPE_FOC  = 2 → mcpwm_foc_init(...) → 磁场定向控制

全局默认：MCCONF_DEFAULT_MOTOR_TYPE = MOTOR_TYPE_FOC
Luna 部分配置写作数值 2，其含义同样是 FOC。

顶层 Makefile 直接提供 fw_<board> 和 <board> 目标。其 help 中还提到 fw / PROJECT=... fw，但当前顶层文件没有定义通用 fw 规则；本文示例使用实际生成的明确板卡目标。

双桥并联是两组三相功率桥共同驱动一台电机。当前代码在配置更新时强制 FOC；它与双电机模式的启动强制逻辑并不完全相同，因此本报告不将二者的初始化约束混写为同一条。

几个容易误判的目标

  • 40 / 410 / 45 / 46 / 48 / 49 等 VESC4 系列：仍然全部默认 FOC，同时保留六步模式入口，不能归为“仅六步”。
  • 60 / 60_mk* / 75_300 / 100_250 以及 Cheap_FOCer / Little_FOCer / go_foc_*：按本次预处理结果属于模式可选类；名称中的 FOC 不能作为“FOC 专用”证据。
  • a50s_dual_8s / a50s_dual_12s：其 hw_a50s_dual_core.h 没有定义 HW_HAS_DUAL_MOTORS，本工程每个目标按一路控制配置编译，仍归为模式可选类。
  • ubox_v*、go_foc_dv6_pro：本次目标同样没有定义上述双电机限制宏；商品是否含两块 MCU 或两路功率级，需结合硬件原理图判断。
  • _no_limits 变体表示硬件配置限值处理发生变化；实际宏状态可在内嵌审计数据中查看。它不会自动切换六步或 FOC。
